# Lab Model Orchestration Governing Predicates

Status: review-only lab predicate seed.  
Claim ceiling: model-role governance planning.  
Activation status: non-binding, non-executive, non-authorizing.

This note captures the current lab posture for model-role orchestration before any live model binding, provider call, runtime hydration, `CME.Actual`, or `Sanctuary.Actual` standing is admitted.

It exists to keep the first working instrument body from confusing model capability with governing authority.

## Governing Compression

> A model may participate in the instrument.
>
> A model may not become the warrant rail.
>
> Codex may build and audit governing bodies.
>
> Codex may not become sovereign runtime authority.
>
> Smaller model bodies may instantiate bounded CME workers.
>
> No instantiated worker may self-authorize.

## Current Non-Activation Boundary

This note does not:

- select a production model
- bind an API key
- call a provider
- export model context
- authorize training use
- admit model memory
- activate runtime identity
- admit `CME.Actual`
- admit `Sanctuary.Actual`
- grant `SLI.Lisp` evaluation
- grant database write
- grant `GEL` promotion

The current line manifest remains true: promotion to run-pointing cold truth does not grant model binding, Lisp evaluation, database write, `GEL` promotion, `CME.Actual`, `Sanctuary.Actual`, or live runtime authority.

## Model Role Classes

| Role Class | Preferred Lab Source | Function | Non-Grant |
|---|---|---|---|
| Main Body Engine | OpenAI frontier GPT / ChatGPT-class model | Dialogos, reconstruction, meaning formation, long-context reasoning, operator-facing articulation. | Not warrant rail, not runtime authority, not self-certifying CME life. |
| Governing Build And Audit Body | Codex / Codex-class coding agent | Code walking, contract hardening, test generation, refusal-surface inspection, implementation review. | Not sovereign Steward, not runtime judge, not cryptographic authority, not live governance. |
| Instantiated CME Worker Body | OpenAI smaller GPT mini/nano/micro-class profile | Bounded task participation under local contracts; low-cost, role-scoped cognitive work. | No self-authorization, no direct `GEL` promotion, no authority inheritance, no domain widening. |
| Comparative External Model Surface | Non-primary or external LLMs | Comparison, translation stress, robustness check, collapse detection, adversarial interpretation. | Not seed authority, not continuity source, not warrant, not internal identity basis. |
| Deterministic Governance Rail | Local C#, `SLI.Lisp`, receipts, tests, manifests | Final pass/refuse/route/persist/activate decision surfaces. | Not dialogos by itself; it governs admission and refusal. |

## Primary Seed Predicate Posture

Primary lab seed predicates should remain:

- OpenAI-proximal
- provenance-labeled
- reviewable
- non-sovereign
- non-self-authorizing
- steward-routable
- separable from external comparison material

The reason is not provider worship. The reason is continuity discipline: the current lab language body, Codex build posture, ChatGPT theory posture, refusal law, and operator-mediated conversational practice have formed inside an OpenAI-proximal instrument field.

Therefore, the first seed predicate lane should preserve that provenance rather than mixing unrelated model-body assumptions into the earliest continuity substrate.

## External Model Predicate

External LLMs may be used to ask:

- where does another model collapse the boundary
- which doctrine terms fail under translation
- which contracts depend too heavily on one model family's language habits
- which claims remain reconstructable across model families
- where does fluency impersonate warrant
- where does refusal fail or overfire

External LLM outputs may not enter:

- `GEL`
- `SelfGEL`
- `OE`
- `cSelfGEL`
- seed predicate standing
- governing memory
- role authority
- continuity basis

without explicit provenance labeling, Steward review, witness receipt, and a separate admission gate.

## Main Body Engine Predicate

The main body engine may:

- hold dialogos
- reconstruct operator pointing
- surface ambiguity
- propose thought status
- request evidence
- prepare review-only candidate claims
- support participatory knowing
- return bounded articulation

It may not:

- become the final warrant rail
- treat fluency as authority
- import external authority silently
- admit its own conclusions to continuity
- promote thought into action
- mutate `SelfGEL`
- claim `CME.Actual`
- claim `Sanctuary.Actual`

## Codex Governance Predicate

Codex may:

- build code
- inspect code
- generate tests
- execute local verification
- harden contracts
- map doctrine into typed surfaces
- identify implementation drift
- prepare patches
- report evidence

Codex may not:

- authorize runtime activation
- grant model binding
- bypass Steward
- self-certify governance
- overrule local C# / `SLI.Lisp` rail
- treat successful build as warrant
- treat test green as `CME.Actual`

Codex is a build and audit instrument. It is not the sovereign governance body.

## Instantiated CME Worker Predicate

Instantiated CME worker bodies should be:

- smaller-model profile candidates
- role-scoped
- bounded by local contracts
- receipt-emitting
- default-deny
- non-promotional
- revocable
- queryable by Steward
- unable to widen their own authority

They may perform:

- bounded summarization
- local reconstruction
- classification
- drafting
- comparison
- safe rehearsal
- evidence request formation
- review-only branch work

They may not perform:

- self-authorization
- domain escalation
- live external action
- Special Case inheritance
- Military / Defense operational work
- legal, medical, financial, emergency, or governmental determination
- raw protected intake exposure
- `GEL` promotion
- `SelfGEL` mutation
- `CME.Actual` claims

## Deterministic Governance Predicate

The final local rail for the first working instrument body should remain:

- C# contracts
- `SLI.Lisp` carrier grammar
- receipts
- tests
- manifests
- local verification
- Steward-routable refusal surfaces

Models may propose. The rail disposes.

The rail should decide:

- pass
- refuse
- withhold
- route
- cool
- retain
- replay
- query
- escalate to HITL

The rail may not pretend to be dialogos, but it must govern what dialogos can promote.

## Model Binding Gate

Future model binding requires at minimum:

- model role declaration
- provider provenance
- model identifier
- capability class
- cost/latency class
- data exposure policy
- context export policy
- permitted surfaces
- forbidden surfaces
- receipt emission path
- refusal path
- Steward review path
- HITL gate where needed

No model binding may occur merely because the cold bench is complete.
