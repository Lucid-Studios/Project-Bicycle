# REGIONAL_ATLAS_PACKAGE_ADMISSION_BEFORE_GEL_FORMATION_LAW

## Purpose

This note defines the first regional Atlas package admission seam in
`V1.2.1`.

It exists to keep universal Atlas authority, localized assent footing,
regional package admission, and first local `.GEL` formation in the correct
order.

## Governing Compression

> universal Atlas authority remains lab-side.
> local install admits only one bounded regional Atlas derivative.
> regional Atlas package admission occurs after localized assent footing and
> before first runtime-admitted `Sanctuary.GEL` formation.
> local telemetry and local symbolic footing may bind only to the admitted
> regional package, not to the whole universal Atlas family.

## Working Order

The install-first order now reads:

`Download -> LocalizedInstallChoiceMatrix -> AgreementPredicateBundle -> InstallIdentitySetCandidate -> first regional configuration -> regional Atlas package admission -> first runtime-admitted Sanctuary.GEL formation`

This order is constitutional for the current phase.

No local `.GEL` formation may bypass admitted regional package footing.

## Universal And Regional Boundary

Lab holds the broader universal Atlas family across major regional language
groups.

Local install receives only:

- one signed, bounded regional derivative
- one receipted regional package admission
- one local package basis for symbolic footing, telemetry, and first `.GEL`
  formation

No runtime note may treat local regional package selection as ownership of
universal Atlas authority.

## First Package Office

The first admitted package in this phase is:

- `EnglishRegionalAtlasPackage`

Its language group is:

- `English`

Its current purposes are:

- local install footing
- symbolic transform basis
- first `.GEL` formation input
- regional telemetry

This phase does not yet admit:

- multi-package local coexistence
- runtime switching across language groups
- local universal-family aggregation
- top-10 language rollout logic

## Admission Inputs

The first regional Atlas package admission must be bounded by:

- localized install choice / locale footing
- agreement-derived install identity basis already formed upstream
- package language-group identity
- signed payload lineage
- package witness and verification witness

It may not be bounded by:

- raw `RootAtlas` body
- universal Atlas body
- direct lab-side mutation authority

## Local Telemetry Rule

Local telemetry in this phase may bind only to the admitted regional package
for the install.

It may not claim:

- telemetry over the full universal Atlas family
- runtime ownership of non-admitted language groups
- runtime authority to widen package scope after admission

## Explicit Non-Grants

This note does not authorize:

- package download logic
- live remote fetch
- universal-family runtime aggregation
- direct `.GEL` formation by package presence alone
- return-to-Prime
- public-readable derivative generation

Regional package admission is prerequisite footing, not later consequence.

Regional package admission does not directly form `.GEL`.
It contributes one bounded member to the later formation data pool.

## Working Summary

`V1.2.1` now names the first pre-`.GEL` regional Atlas package seam.

That seam admits one bounded English regional package after localized assent
footing and before first local `.GEL` formation while keeping universal Atlas
authority in the lab-side family.
