## Build Objective

The next milestone is not a live awakened runtime.

The next milestone is a first working cold instrument body:

```text
operator input / thought form
-> Listening Frame
-> Compass pressure
-> Discernment
-> SLI/GEL-held candidate posture
-> Steward warrant / refusal
-> receipt
-> review-only output
```

The instrument should be able to:

- accept a bounded thought/event candidate
- classify its thought status
- identify missing warrant and category pressure
- return principled refusal when needed
- route safe exploration lanes
- retain evidence and witness references
- keep model role participation outside final warrant
- refuse activation and runtime self-authorization

## Pass 1: Dialogos / Discernment Contract Run

### Initial Concept

Convert `CME_DIALOGOS_DISCERNMENT_AND_WARRANT_LAW.md` into typed cold contracts. The system must distinguish thought appearance from thought status and make principled refusal representable.

### Expected Deliverables

- `ThoughtStatus` enum
- `DiscernmentRecord`
- `PrincipledRefusalReceipt`
- `WarrantBoundary`
- `ArticulationSurface`
- `IntermediateChamberState`
- `ReturnPath`
- `SafeExplorationLane`
- SLI.Lisp inert carrier forms for discernment and refusal
- tests proving:
  - articulation is not warrant
  - internal coherence is not external warrant
  - model-model agreement is not evidence
  - thought appearance cannot self-select admitted status
  - refusal preserves safe exploration when available
  - authority defaults to `not-authorized`
- new spiral cells for dialogos/discernment artifacts

### Acceptable Variance

- names may shift if existing code conventions demand shorter forms
- `ThoughtStatus` may be split into status and disposition if tests read cleaner
- safe exploration may initially be a string/list rather than a rich typed route
- SLI.Lisp carriers may remain inert review bodies only

### Refusal / Stop Conditions

- any implementation grants action authority
- any implementation treats a fluent claim as admitted by default
- any implementation collapses refusal into generic safety refusal without premise load
- any implementation uses a model call
- any implementation promotes to `GEL`, `SelfGEL`, `CME.Actual`, or runtime identity

## Pass 4: Steward Warrant And Principled Refusal Run

### Initial Concept

Build the refusal/warrant surface that lets the instrument say no with context. This is the core discernment advantage: refusal should explain premise load, missing warrant, category pressure, safe lane, and evidence needed.

### Expected Deliverables

- `StewardWarrantReview`
- `WarrantDisposition`
- `PremiseLoad`
- `CategoryPressure`
- `MissingWarrant`
- `EvidenceRequirement`
- `SafeExplorationRoute`
- principled refusal markdown/json receipts
- tests proving:
  - refusal is not abandonment
  - refusal is not erasure
  - refusal can preserve safe exploration
  - missing warrant blocks admission
  - category pressure blocks collapse
  - operator desire is not authorization
  - institutional proximity is not warrant
  - credential is not omniscience
  - non-credential is not incapability

### Acceptable Variance

- `PremiseLoad` and `CategoryPressure` may start as lightweight records
- safe route can be optional when no safe lane remains
- the refusal receipt may be reused by pedagogy and model role runs

### Refusal / Stop Conditions

- refusal becomes generic, context-free safety text
- refusal cannot identify missing warrant
- refusal cannot preserve safe exploration when safe exploration exists
- refusal admits the claim because it is coherent
- refusal routes to action without separate admission

## Pass 5: First Instrument Harness Run

### Initial Concept

Create the first cold end-to-end harness. The harness should accept sample thought/event candidates and emit a review-only trace through listening, Compass, discernment, Steward review, refusal/admission candidate, and receipt.

### Expected Deliverables

- CLI command such as `instrument-trace` or `cold-instrument-trace`
- sample fixtures:
  - speculative ontology with high coherence but no warrant
  - ordinary educational reconstruction candidate
  - Special Case-sensitive training branch
  - model-role candidate
- JSON and markdown trace reports
- tests proving:
  - no model provider call
  - no runtime activation
  - no `SLI.Lisp` evaluation
  - no database write
  - no `GEL` promotion
  - no `CME.Actual`
  - no `Sanctuary.Actual`
  - receipt preserves lineage and thought status
  - review-only output is produced

### Acceptable Variance

- fixture input may be JSON files before interactive CLI input exists
- Listening Frame may be represented as a cold intake record
- output can be deterministic and rule-based
- no natural-language generation is required

### Refusal / Stop Conditions

- command performs model calls
- command accepts live external actions
- command writes beyond receipt/artifact path
- command treats trace completion as activation
- command grants action or authority from a sample fixture
