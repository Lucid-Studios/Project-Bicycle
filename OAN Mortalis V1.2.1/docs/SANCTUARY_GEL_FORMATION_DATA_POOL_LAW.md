# SANCTUARY_GEL_FORMATION_DATA_POOL_LAW

## Purpose

This note defines the pre-`.GEL` formation data pool in `V1.2.1`.

It exists so first `Sanctuary.GEL` formation receives one bounded install-side
inheritance body rather than a loose handful of neighboring prerequisites.

## Governing Compression

> the formation data pool is the immediate upstream body for first
> `Sanctuary.GEL` formation.
> it gathers credential footing, assent footing, bounded use posture, regional
> Atlas package footing, and bounded lab predicate inheritance into one local
> install-side inheritance body.
> uncertified or unauthorized communications may terminate in `Silence` before
> yielding a useful listening response surface.

## Production Order

The pool is produced only after:

`LocalizedInstallChoiceMatrix -> AgreementPredicateBundle -> InstallIdentitySetCandidate -> CoreCmeUsePostureRecord -> site/regional footing -> admitted regional Atlas package`

This body is the first lawful pre-`.GEL` inheritance pool.

It does not form `.GEL` directly.

It yields the bounded predicate-bearing pool from which first `.GEL` may later
form.

It is not `.GEL` yet.

## First Pool Members

The first pool set is:

- credential footing
  - licensing agent identity
  - user identity
- assent and install identity footing
  - `LocalizedInstallChoiceMatrix`
  - `AgreementPredicateBundle`
  - `InstallIdentitySetCandidate`
- bounded use posture
  - `CoreCmeUsePostureRecord`
- regional footing
  - active language
  - locale
  - jurisdiction
  - admitted English regional package
- lab predicate inheritance
  - bounded predicate lineage summary
  - inherited predicate witness
- optional site footing
  - `CradleTekSiteBindingProfile` when present

## Disposition Grammar

The pool may stand in exactly one posture:

- `Ready`
- `Silence`
- `Refused`

`Ready` means:

- lawful bounded pool available for first `.GEL` formation

`Silence` means:

- uncertified or unauthorized communication posture
- the line must not expose a useful listening response surface

`Refused` means:

- explicit bounded refusal in a recognized install-facing lane
- the caller may receive a named denial

## Silence Rule

`Silence` is a security posture, not an error-handling convenience.

It exists to avoid teaching uncertified communications how to probe listening
posts.

At minimum, this phase may yield `Silence` for:

- missing or unrecognized credential footing
- local claims of universal Atlas authority
- install-adjacent communications that fail certification or witness burden
  before lawful footing exists

## Refusal Rule

At minimum, this phase may yield `Refused` for:

- recognized install-lane communication with missing install identity
- recognized install-lane communication with missing admitted regional package
- recognized install-lane communication with missing predicate inheritance
- recognized install-lane communication with incomplete required posture

## Non-Collapse Rules

The formation data pool is:

- bounded and local
- immediate upstream footing for first `.GEL`
- lawful install-side inheritance body

It is not:

- universal Atlas authority
- lab-source sovereignty
- runtime activation
- cryptic posture itself
- public derivative output

Future cryptic posture may inherit localized governing standing from this body.
It may not inherit that standing from raw contract law alone.

The install-first line may already carry implicit typed predicate structure
through this pool and its downstream predicate pool without surfacing explicit
validator behavior yet.

## Working Summary

`V1.2.1` now has a named formation data pool above first `.GEL`.

That pool gathers credentials, assent footing, bounded use posture, admitted
English regional package footing, optional site footing, and bounded lab
predicate inheritance into one local inheritance body while preserving
`Ready`, `Silence`, and `Refused` as distinct security and governance
postures.
